# FERB 0.26 audit

Baseline: `88368e8` (0.25.0). Audit performed 5 October 2026, before production fixes. Lines below refer to that baseline unless a closure says otherwise. Private traces stay outside Git; task/span IDs make the evidence reproducible with `ferb trace TASK --full`.

## Ten riskiest findings, in plain language

1. An embedded file input was rejected. The model then chose a same-name Drive file and falsely described it as the local file. The checker never established the uploaded content.
2. Short study guides passed because words from the syllabus appeared somewhere in them. Nobody established that a beginner could actually learn from them.
3. The checker could not see memory already written by chat. It also failed paths present in artifact data because they were absent from prose.
4. Cleanup review could generate a success claim after failed checks. The final formatter put both claims in the same answer.
5. Native foreground interactions still restored an old app, potentially overriding what the owner deliberately chose next.
6. File, profile, app, window and option helpers still chose first/prefix matches, including silently correcting file paths.
7. Context and source snapshots discarded text without recoverable markers. Pasted request data was lost between planning and execution even though plain owner words survived.
8. A fixed Gmail sender picked a Send button by its label and accepted an old same-subject message as proof of delivery.
9. Indirect shell/AppleScript actions could take focus. There was no continuous task-side measurement of Space, key window, cursor, full screen and order.
10. Several tools limited artifact-bearing inputs, and some returned only clipped source text. These limits could pressure models to shorten work or mistake partial evidence for complete evidence.

## Audit method and coverage

First pass: study agent (orchestrator, prompts, runtimes); browser agent (browser drivers, extension, native host, account operations); background agent (native Mac, shell/files, device/voice/CLI, cross-cutting background); root (daemon/gateway/questions, stores/registry/policy/core, memory/sense/clock/decide, tests/docs/retained experiments). Second pass rotated reviewers: study agent reviewed browser identity/upload/sending, browser agent reviewed background, background agent reviewed context/checking. No code fixes preceded incident regressions and these passes. Jev extension hooks are intentional and retained.

The inventory deduplicates identical finding rows. Overlapping locations with distinct mechanisms remain separate. Historical disturbance rows distinguish recorded changes, merely capable actions and unknown attribution. This is a source audit, not proof of all possible model behavior.

## Closure ledger

The area closure tables at the end map the audited findings to removals, model judgment, exposed facts or justified mechanics. Regressions were first red against the baseline, then green after fixes. Independent reviewers rotated across source/target selection, context/checking and background paths. Final combined validation and installation receipts are in the 0.26 changelog and evidence directory. A passing fixture is not broad live acceptance.

## Decisions for parent to record

- Do not “fix” study length by minimum word count. Options: fixed number, automatic syllabus keyword completeness, model depth rubric against full request. Choose last: requested usefulness is judgment; term count was the failed approximation.

- Existing worker original-request path is preserved, not rebuilt on a false incident hypothesis. Checker/intake access genuinely needs repair.

Pointer30s freshness and32 points per screenshot are stale-reference/resource bounds; fresh screenshot is available. Protocol/HMAC/origin/reference checks, exact known profile folders, password redaction and private FERB mailbox-origin restriction are harness mechanics, not intent decisions. Current char/item snapshot clips and first-match resolution are not justified by merely naming “bounded context”: they need full retrieval or removal.

## Sentinel design and primary sources

- Use `NSWorkspace.sharedWorkspace().notificationCenter()` with `NSWorkspaceActiveSpaceDidChangeNotification` on a live run loop. Apple states this posts when a Spaces change occurs and has **no userInfo**. A monotonically increasing transition epoch is the honest public fact; not a stable Space ID. https://developer.apple.com/documentation/appkit/nsworkspace/activespacedidchangenotification
- Collect CGWindowList onscreen ordered `(window_id,pid,layer,bounds)` without window titles. Record appearance/removal separately from reorder. Apple describes selected user-session window metadata and warns that dictionary generation is expensive; profile sampling cost. NULL outside GUI session is unavailable, never empty/unchanged proof. https://developer.apple.com/documentation/coregraphics/cgwindowlistcopywindowinfo(_:_:)
- Read systemwide AX focused app, then AXFocusedWindow fingerprint and AXFullScreen when supported; distinguish missing key-window metadata from false fullscreen. Reading key window by AX id may require bounds/id matching; report ambiguous mapping. Public API cannot establish private Space numeric identity.
- Cursor via CGEventGetLocation; sample before/after every action plus 250ms while task runs through cleanup. Do not touch mouse or ask for screen capture permission.
- Include action spans active and recently ended, thread times, owner input recent. These are temporal correlations, not proof FERB caused each change. Owner movements during work must remain facts with attribution unknown, rather than all labelled unauthorized FERB disturbances.
- New notification observer run-loop health and read errors must be present in task trace; a zero-event log with no working observer is not pass.
- Dedicated Space/virtual display is only research. Public notification does not provide control or stable identity. Do not ship new private Space movement; existing private input transport remains explicitly limited.

## Highest risks

1. **Foreground restoration still exists in native code.** `driver._forward` saves the prior app; `_restore_later` schedules `restore_owner`; that reactivates the saved app when the target app remains frontmost. It cannot distinguish “target stayed frontmost because FERB activated it” from “owner deliberately chose to remain there.” This violates the new explicit “Restore nothing afterwards,” even though 0.24 made restoration conditional and avoided restoring over a *different* owner-selected app.

## Root retained limits and reasons

These are explicit boundaries, not a promise of unlimited machine resources. No retained limit is a deliverable
word-count target. Browser/native/runtime details are listed in the area closure sections below.

- RPC input1MiB is an owner-only framing/memory boundary: oversize returns `-32002` and closes; it never executes
  a cut message. Multi-action file work or shell/file operations can produce larger artifacts. Native messaging
  additionally supports multipart content. CLI JSON trace output is complete.
- `task.evidence` previews500 characters with `input_truncated` and exact span-ID fetch; pages have a next cursor.
  Compact CLI trace previews are not stored source; `--full` and `--json` show full redacted data.
- Context default32,768 tokens, with prompt/schema reserves and protected-request overflow reporting. Optional
  blocks are omitted whole with retrieval markers. Actual provider windows/output budgets remain external limits.
  Token estimation method is recorded; UTF8-byte ceiling fallback is conservative and never clips source text.
- Memory recall8 and daily lexical search8 are labelled retrieval subsets, not complete lists or action-target
  resolutions. Query matching uses full words; `memory.read`, `chat.history`, `trail.query` and stored context sources
  expose complete underlying evidence. SQL/FTS ranking can miss semantic synonyms; the agent can inspect broader data.
- Question600s expiration protects a stale pending answer; expired/unattended questions never consent. The caller can
  configure wait duration in the question broker. Duplicate options/free text are not forced into a guessed choice.
- Sentinel250ms plus tool boundaries/public Space notifications is sampled observation. Short changes may be missed;
  AX unavailable fields are explicit, full-screen is the focused-window attribute, and Space identity is a transition
  epoch. It records timing, not exclusive causation. No private Space manipulation or automatic focus restoration.
- Event bus bounded queues drop only telemetry with a count notification; critical overflow disconnects explicitly.
  Durable spans/journal writes precede publishing. A slow client cannot silently erase the durable task record.
- Jev12,000-character state bound refuses full call instead of cutting; optional shadow queue200 records drop facts;
  diagnostic stats last20 are labelled a recent sample. These do not shorten user tasks or change target choices.
- Activity focus intervals cap one estimated gap at3600s, labelled in digest; this prevents attributing an unobserved
  overnight interval as app usage. It is an estimate, never elapsed task proof. Raw trail retention30days requires
  a daily summary first. Privacy exclusions/redaction are intentional and remain separate from context omission.
- Observed memory proposals require three distinct source days before activation; retained as a conservative
  publication/provenance threshold, not proof of a preference or authorization. Model-produced proposals retain
  observed origin and conflict evidence; agents must judge applicability. Owner-stated facts use their own provenance.
- Typed calendar weekday/date arithmetic remains code mechanics; no fuzzy phrase parser was added. PEP495 wall-time
  default uses first occurrence on a DST overlap and moves through a gap; recurrence next-run scan9days covers the
  supported daily/weekday/weekly grammar. These semantics are documented, but explicit DST-overlap selection is not
  implemented. Local India-zone tests do not establish other-zone user intent; callers should clarify unusual times.
- Hash lengths, stable IDs, schema enums, authentication sizes, migration numbers, process versions and platform key
  maps are mechanical identifiers/protocol constraints. They do not select an owner file/account/profile. Installer
  pinned-interpreter discovery and PATH executable lookup are deployment mechanics, not task-target resolution.
- Retained privacy recognition (secret field/types/URL parameter keys), watcher exclusions and binary/frame rejection
  can omit data intentionally. The privacy marker/refusal must remain visible; secret recovery is intentionally absent.

## Remaining limits and reasons (browser area)

- **Initial preview only:** 8,000 text characters plus a 24,000-character element-row budget. No field is shortened; omitted rows/text carry explicit markers and browser.read obtains the complete stable snapshot. Read/find pages default12,000 characters, caller-selectable1..100,000, with next_offset and total_chars. This is paging, not a deliverable cap. Supervisor context token budgeting is separate root work.
- **Transport frames:** native messaging1MiB and extension message schema1MiB; install IDs8..64 characters. Large commands/results use100,000-character ASCII JSON chunks; command chunking starts above500,000. Chunks reassemble before executing once. No total artifact/text limit. Lost partial transfer after extension restart requires fresh inspection, not replay of a consequential command. Chunk caches live only in extension process memory and are discarded when fully read/assembled; interrupted transfers persist until process restart.
- **Command liveness:** defaults30s with5s daemon acknowledgment margin; opens/navigation/snapshot/act/upload/find30s, scroll/secret fill15s, feed20s, inventory/dialog/close/release/point10s, ping5s, pointer cancellation2s. Timeouts can abort a legitimate slow operation but surface unknown outcomes; never truncate text or infer no side effect. Long work may choose another explicit method. No automatic action retries.
- **Connection mechanics:** windowless wake8s; native pairing page request read5s; handshake15s; keepalive15s; reconnect exponential backoff1s to60s; extension alarm30s. Single-use pairing token300s. These concern transport readiness and security, not owner task deadlines or target meaning.
- **Replay summaries:** extension caches500 seen IDs, hello advertises last200. Persistent daemon ledger records full actions and treats absent cache evidence as unknown. No duplicate retry is inferred. Process-memory outbox has no evidence-drop cap.
- **Visual freshness:** screenshot references30s and at most32 points before a new screenshot; each gesture consumes its screenshot. Prevents stale geometry, not task effort. Same-frame drag only; transformed/inaccessible frame bindings refuse explicitly. Pointer readiness20x25ms and initial input readiness20x100ms are observation attempts; no alternate input route. Drag20 interpolation steps at20ms with surface checks every5 steps is geometry mechanics. Scroll settle8x60ms and step85% viewport is one requested screen movement; agent can observe/repeat.
- **Known geometry:** owned tab viewport1280x900, deviceScaleFactor1, pointer position tolerance1px and privacy-window bounds tolerance2px. Ambiguous window/binding never selects first. Borrowed owner tabs keep actual geometry. AX role maps and HTML input/role lists translate platform types only; unknown/closed-shadow/canvas controls require explicit screenshot/point evidence and may be unsupported.
- **Passwords/URL redaction:** hidden values, authentication query parameters and parameter-style fragments are redacted. Full-secret retrieval is intentionally unavailable; only origin-bound sealed fields receive them. This is an explicit privacy rule, not source clipping.
- **OTP provider coverage:** Gmail Atom exposes unread inbox entries only, from configured dedicated FERB profile; exact configured address must match. Candidate grammar currently numeric strings of at least4 digits (including year-shaped values); it does not infer that any is an OTP. Subject/body are withheld entirely so alphanumeric or other unsupported secrets cannot escape through context. Only sender, date, source, account, message identity and opaque numeric candidate metadata reach the agent. Alphanumeric or shorter codes require another explicit route; no automatic best/latest choice. If these metadata cannot establish identity, ask the owner or choose another explicit route. Used message IDs cannot be reused. Account/origin mismatch refuses. Not live-tested against an account during this pass.
- **Browser availability:** installed code supports Chrome and Brave profile metadata/extension transport. Existing real personal profiles and provider services were intentionally not exercised. Chrome disposable background was measured; Brave and provider-specific Gmail/Drive/Calendar/Forms outcomes remain unverified in this pass. Pairing/update UI is an explicit owner setup foreground step, not a background task route.
- **Snapshot/search retrieval freshness:** browser.read pages a saved snapshot; browser.find starts a fresh complete inventory only at offset=0 and pages the saved same-query inventory thereafter. Full search candidates cannot shift between pages. Evidence is an observed historical view, so agents still refresh before consequential action; tab cleanup frees these saved views. Added red then green changing-page regression.
- **Disturbance coverage:** sampled250ms with before/after action samples and Space transition notifications; short changes may be missed. Current frontmost app did not expose AXFullScreen. Zero observed change is evidence, not proof for other Spaces/fullscreen/browser builds.

## Decisions made for the owner

1. Keep semantic Gmail send helper or retire? Retired it, preserving email via explicit browser primitives, because first-Send/subject-only receipt cannot prove recipient/account/body identity. No undocumented compatibility wrapper.
2. Keep automatic OTP newest selection or ask agent to choose candidates? Chose opaque evidence inventory; preserves sealed codes while making identity/time judgments explicit. Did not implement arbitrary alphanumeric extraction without a trustworthy provider format.
   Final privacy review decision: expose masked message context / infer more secret patterns / withhold subject and body? Chose withholding. Numeric-only masking leaked alphanumeric codes when another numeric string created a candidate; regex guesses cannot guarantee sealed content. This limits automatic identity evidence and can require an owner question or another explicit route.
3. Freeze unexpected JavaScript dialogs or automatically dismiss to keep tasks moving? Keep pending and expose browser.dialog. Dismiss/accept changes page state; uncertainty must not silently choose. Verified no observed OS disturbance in disposable Chrome.
4. Reuse a same-name tab group or drop cosmetic grouping? Dropped grouping: it has no task capability benefit and avoids hidden first-match behavior.
5. Treat local upload success as final submission proof? Only assert direct file-input transfer and byte equality; remote destination/account/submission remain checker/model evidence responsibilities.
6. Allow a “background” URL launch during pairing? Refuse at the generic launcher; pairing explicitly marks foreground setup because owner invoked pairing. Ordinary task wake remains windowless, with no silent foreground fallback.
7. Per-message transport cap vs arbitrarily large content? Kept Chromium's physical frame bound, added multipart framing; no overall content cap or silent shortening.
8. Preserve500-ID replay cache or grow session storage forever? Kept the cache as a reconnect hint; durable daemon ledger remains authoritative and unknown cannot be replayed. Reported the distinct200-ID hello window rather than pretending complete history.
