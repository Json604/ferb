# FERB Notch

Native macOS 14+ front end for the local FERB daemon. The notch geometry, pinning, shortcuts, Spaces behavior, sounds and reduced-motion handling are preserved from the existing design.

## Run

Install/update the backend from `~/Desktop/FERB` with `ferb setup --update`. Build this app with `./build.sh`, then open `build/FERB Notch.app`. The app connects to `~/.ferb/run/ferb.sock`; it does not start, install or restart the daemon. Profile → Reconnect to FERB reconnects without resubmitting a request. Closing the notch or quitting the app leaves daemon tasks running. Stop targets the selected backend task, including when Stop was pressed before planning finished.

The socket authenticates as the owner CLI. `chat.attach` resumes the conversation. `chat.send` streams actual task progress and results. `logs.subscribe` observes background changes, and read-only `chat.status`/`trace.get` reconcile running tasks, pending prompts and completed results after disconnect. The UI persists its conversation turns, timestamps, task IDs, answers and artifact paths locally in preferences. Today is one continuous chat; the visible History control opens date tabs for earlier days. The daemon conversation ID stays the same across days. Existing CLI-only transcripts are not imported by the current daemon RPC. The backend retains its normal task records.

Attachments are sent as explicit file paths only when the daemon advertises `input_paths`; older daemons show an update requirement instead of dropping the files. Pasted reference text retains data provenance. If the draft is edited after pasting, the owner explicitly chooses whether the whole draft is their request or reference material. Control escape characters in reference text are represented visibly as `\u001b` to prevent forged frame delimiters.

Password, OTP and secret requests use a separate secure field, with task identity shown. Hidden values never enter the normal composer, UI history or activity. The field clears before sending, when changing prompts and when hiding the surface. Requests are not automatically retried after an uncertain connection failure. Free-text and hidden answers use `chat.answer`. Option buttons send their exact one-based ordinal through `chat.approve`; Cancel/Decline uses `chat.approve` with `granted: false`.

Results show the actual daemon answer and reported status; an unverified or failed result is not labelled Done. Only explicit absolute artifact paths become Open, Quick Look, Reveal and drag actions. No example PDF is generated by task submission or file actions.

Dictation now uses AVAudioEngine and Apple Speech in the notch app. Click the microphone or hold right Command + Option; release or Stop ends capture and places the real transcript in the composer for review. Microphone and Speech Recognition permission are requested on first use. On-device recognition is preferred when available; otherwise Apple Speech may use its servers. No audio files are saved. Cancel, hide, or switch to typing stops capture. Releasing during a permission prompt prevents capture from starting later. Secret approval fields remain separate from dictation and chat history.

Live daemon task events update the working row and activity view immediately. When the installed daemon emits `reply_delta {text}`, the frontend renders those real chunks in the matching turn, labelled “Draft · still responding.” Drafts do not trigger completion sounds, notifications or status. Authoritative `reply`/`clarify` text replaces the draft, while `plan` clears it and switches to task progress. `reply_abort {reason}` or a connection interruption clears the incomplete draft and records an interruption instead of a completed answer. This requires a daemon/runtime that emits real deltas; older daemons still show complete replies without fake typewriter delays. Both final direct replies and task outcomes automatically reveal the notch without requesting keyboard focus. Startup restoration is silent; newly completed tasks recovered during a disconnect still reveal it.

Microphone route changes use the current hardware input format. A small Objective-C boundary converts AVFAudio exceptions into recoverable errors before they can unwind through Swift tasks; cleanup is protected too. The format-change and exception paths have regression tests; live dictation while switching audio devices still needs owner acceptance.

When the daemon finds a missing startup profile, the existing approval view shows the proposed app-use profile and an expandable evidence list. Save, edit or skip uses the same approval contract as the CLI; no preference is confirmed automatically.

## Checks and shipping

Run `swift test` and `./build.sh`. Tests cover a temporary Unix socket server, fragmented RPC framing, auth, stream filtering, approval routing, task recovery, stop-before-plan, provenance, results and existing notch layout/shortcut behavior. They do not call a model or operate the installed daemon.

The current build is locally ad-hoc signed. Public distribution still needs a Developer ID identity, hardened runtime, notarization, versioned backend onboarding/update support and owner live acceptance. The unmanaged SkyLight overlay remains a private API dependency with the existing AppKit fallback; do not describe this build as App Store ready.

The conversation uses compact Messages-style bubbles and a 240-point minimum reading area when messages exist, growing to 320 points before scrolling; the empty dialog remains compact. The native composer consumes Return, accepts Shift–Return for a newline, and keeps IME composition intact. Submission is silent. You can send further messages during work: each local stream tracks its own task, while the daemon orders routing until work is registered (`supervisor.send`) and runs tasks independently. Submitting clears the composer immediately; incoming replies never erase an in-progress draft.

### Task controls and quiet updates (2026-10-11)

Open **Tasks** from chat or an approval to see individual active and completed tasks. **Inspect** shows that task's progress, result, artifacts, and an optional full task record. **Stop task** sends only that task's ID; a request still awaiting its ID remembers its own stop request. There is no ambiguous aggregate Stop button.

Background replies and progress update the transcript/status and completion glow without opening the notch or cancelling dismissal. This follows the owner's latest request and supersedes the earlier automatic answer expansion. Cmd-V uses the native Edit menu and composer shortcut; pasted text retains its provenance.

Daemon `display_text` is shown when supplied, with **Details** retaining the complete reply or ordinary question. Older daemon events and saved history without the field keep their original text. Secret values remain only in the secure answer field.

### Large task records

Inspect keeps the task summary and activity in the notch. **Open full task record** opens the complete JSON export; **Reveal** locates it in Finder. Serialization runs off the UI thread, and private temporary files retain the whole record without a size cap. Switching or hiding an inspection rejects late responses. Socket framing scans each incoming byte once rather than rescanning the accumulated response.

Freeze repair validated 2026-10-13: 99 native tests and release build passed. The owner’s 35.6 MB trace loaded through the patched Swift transport in about 0.5 seconds. Previous samples showed main-thread CoreText layout at 100% CPU, then repeated socket-buffer scanning after UI restart. Only the UI was relaunched; the daemon was not restarted.
